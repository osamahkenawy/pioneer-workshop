# Pioneer Car Service Center — Deployment guide (October 2026 release)

Everything needed to put this release on a server, in one file: the code, the
settings, every SQL file with its path, the check queries, the build, what to do
in the app afterwards, and what can go wrong.

**What this release contains:** the Steps 1–7 job card workflow from the client
document (classification, vehicle + issue, job card, inspection & pricing,
estimate, customer decision & work, QC / collection / gate pass / close), roles
and responsibilities, the CRM cycle, the intake inspection (on screen or paper
upload, customer signature, customer link), the Team Board, the technician app
(`/mechanic`, scan by job-sheet QR / VIN barcode / typed number), the Vehicle
Status Board (`/vehicle-board`, replaces Service Tracking), the workshop customer
portal (`/customer/*`), workshop wording ("Ready for collection") and the
security fixes. More background: `HANDOVER.md` §3 and §5a–5c.

## 1. Before you start

- **Server needs:** Node.js ≥ 18 (developed on Node 22), MySQL 8, pm2, nginx.
- **Back up the database and the uploaded files first:**

  ```bash
  mysqldump -u <DB_USER> -p --single-transaction --routines <DB_NAME> > backup_$(date +%F).sql
  tar czf uploads_$(date +%F).tgz car-workshop-backend/uploads car-workshop-backend/private-uploads 2>/dev/null
  ```

- **Never run the QA suites (`car-workshop-backend/scripts/qa/*.mjs`) on the
  server.** They create test users and data, then delete every row above their
  start id in every table. They refuse to run unless `DB_HOST` is `localhost` /
  `127.0.0.1` — on a server where MySQL is local, that guard does not protect you.
- **Do not create the `qa_*` test accounts** on the server; they exist only on the
  development Mac.
- **Do not use `deploy/deploy-server.sh` as it is.** It is from the old setup: it
  resets to `main`, clones an old separate frontend repo, and only runs the base
  schema files. Follow this guide instead.

## 4. Settings

### 4.1 Backend — `car-workshop-backend/.env`

`.env` is **not** in git. Copy the one from the current server (or start from
`car-workshop-backend/.env.example`), then check every line in this table:

| Variable | Value on the server | Why it matters |
|---|---|---|
| `NODE_ENV` | `production` | |
| `PORT` | `4000` | nginx proxies `/api/` here (`deploy/car-workshop-nginx.conf`) |
| `FRONTEND_URL` | `https://<your app host>` — no trailing slash | **Every link sent to a customer is built on it:** status page `/service-status/…`, inspection `/inspection/…`, estimate approval, portal `/customer/set-password…`. A wrong value = dead links for customers. |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | the server's MySQL | |
| `JWT_SECRET` | long random value (`openssl rand -hex 32`) | see §12 — rotate it |
| `DISABLE_CRON_JOBS` | `false` on the one main server | runs service reminders, parts-arrival alerts, job-delay alerts |
| `REMINDER_CRON` | `30 7 * * *` | time of the daily service-reminder run (`CRON_TZ=Asia/Dubai`) |
| `ENABLE_DATA_RETENTION` | **`false`** | inherited job that **deletes** old data |
| `ENABLE_ACCEPTANCE_TIMEOUT` | **`false`** | inherited job that **un-assigns** technicians |
| `ENABLE_TRIAL_ENFORCER` | **`false`** | inherited job that suspends workshops |
| `ALLOW_PUBLIC_SIGNUP` | `false` | customers get portal access from staff ("Give portal access") |
| `ENABLE_API_DOCS` | `false` | Swagger off in production |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURE` / `SMTP_USER` / `SMTP_PASSWORD` / `SMTP_FROM` / `SMTP_FROM_NAME` | the workshop mail account | without it, e-mail sends report "The e-mail was not sent" (WhatsApp and Copy link still work) |
| `SMS_PROVIDER` / `TWILIO_*` | if SMS is bought | blank = SMS are only logged, not sent |
| `GOOGLE_FORM_TOKEN` | only if the Google Form survey webhook is used | blank = webhook refused |
| `SEED_ADMIN_PASSWORD` | leave blank | only for `npm run seed` (demo data) |

### 4.2 Frontend

The build reads `VITE_API_URL` (default `/api`). Leave it unset when nginx serves
the app and proxies `/api/` to the backend on the same host (the setup in
`deploy/car-workshop-nginx.conf`). Only if the API is on another host:

## 5. Which database path are you on?

| Your situation | Do |
|---|---|
| **A. Updating the current server** (database already running the app) | §6.1 check → §6.2 the 17 new migrations |
| **B. Database restored from an old dump** (older than mid-September 2026) | §6.3 the 17 earlier migrations first, then §6.1 → §6.2 |
| **C. Brand-new empty database** | §6.4 (base schema → post patches → all 34 dated migrations) |

Replace `<DB_USER>` and `<DB_NAME>` everywhere below (production `DB_NAME` has
been `car_workshop`; the development Mac uses `pioneer_workshop`). All commands
run from `car-workshop-backend/`. Every dated migration is **idempotent** (it
checks `information_schema` before changing anything), so running one twice does
nothing — safe to re-run after a failure.

## 6. SQL — files, paths and queries

### 6.1 Check before migrating (must return **no rows**)

`20261011_invoice_number_unique.sql` adds a unique index on invoice numbers; it
cannot build while duplicates exist.

```sql
SELECT workshop_id, invoice_number, COUNT(*) AS n
  FROM invoices
 GROUP BY workshop_id, invoice_number
HAVING COUNT(*) > 1;
```

If it returns rows: keep the oldest invoice of each pair and give the others a new
`INV-…` number, then run it again until it returns nothing.

## 9. After the restart — in the app (as the owner / Workshop Manager)

1. **Notifications → Templates → Reset to defaults** (recommended). The workshop
   still has the old courier texts ("ready for pickup!", "Vehicle Returned",
   "Cash Payment Collected"); the reset replaces them with the four workshop
   messages (Vehicle received, Ready for collection, Job closed, Job cancelled).
   Skip it if the templates were customised on purpose.
2. **Settings → Roles:** check each role's responsibilities (steps) and menu.
3. **Settings → Users:** create the real users and give each a role (Service
   Advisor, Storekeeper / Part Advisor, Supervisor, Workshop Foreman, Team Leader,
   Technician, Workshop Manager).
4. **Team Board → Manage team** (as each Team Leader, or a manager picking a
   team): add the technicians to their team.
5. **Customers → a customer → Give portal access** sends that customer a
   set-password link for `/customer/login`.
6. **Tell the staff about the new rules (client changes, 29 Oct):**
   - every enquiry (Service Advisor, website, Fleet Coordinator link) opens its
     work order straight away;
   - for **external** customers the job card opens only when the customer
     acknowledges the **physical inspection** (signed at the car, from the link,
     in the portal, or the paper form uploaded); internal customers get it at once;
     a Workshop Manager can override with a reason (logged);
   - an estimate can only be raised once the job card is open; parts are priced
     per the customer's preference (Genuine / After-Market / Used) with
     availability and expected delivery; an alternative category is only used
     if the customer approves it;
   - only the Service Advisor, the Supervisor and managers record (fill in,
     sign, complete) the vehicle inspection — other staff can view it;
   - once the inspection is completed or signed, the work order's car and
     customer are locked (open a new work order for another car).

## 11. If something goes wrong — roll back

```bash
# 1. code back to the previous release
cd pioneer-workshop && git checkout main     # (or the commit the server ran before)
(cd car-workshop-backend && npm ci) && (cd car-workshop-frontend && npm ci && npm run build)
sudo cp -r car-workshop-frontend/dist/. /var/www/car-workshop/frontend/
pm2 restart car-workshop-backend

# 2. database back to the backup from §1 (loses anything entered since the backup)
mysql -u <DB_USER> -p <DB_NAME> < backup_YYYY-MM-DD.sql
```

The new migrations only **add** columns, indexes and role menu items; the old
code ignores them, so rolling back the code alone (step 1) usually works without
restoring the database.

## 12. Warnings and open items

- **Rotate the old secrets.** Earlier commits had the real database password and
  JWT secret in `deploy/*.txt` / `deploy/*.sh` (now placeholders, but still in git
  history). Change the MySQL password and `JWT_SECRET` on the server. Changing
  `JWT_SECRET` signs everyone out once.
- **Customer data in the repo.** `car-workshop-backend/src/migrations/data/*.csv`
  (customers, vehicles, invoices from the original import) were committed before
  this release. Keep the repository **private**.
