Detailed Findings

SR-01 — Stored XSS: no output encoding at multiple frontend sinks (CRITICAL)

Backend stores all free-text fields verbatim. The xss npm package is declared in package.json but never imported anywhere in the backend or frontend (grep confirms zero usage).

Input path (no sanitization):

// routes/customer-portal.js:249-262 - INSERT stores customer_name, dropoff_address, description,
// special_instructions, notes, item names exactly as submitted. No encoding, no validation.
// routes/public-api.js - same for /api/public/enquiries (contact_name, message).
// routes/work-orders.js - admin-created work orders accept recipient_name/address fields verbatim.

Sink 1 - admin live-map popups (verified live payload in work order #69):

// frontend src/components/MapView.jsx:193
<span dangerouslySetInnerHTML={{ __html: m.popup }} />
// m.popup is an HTML string assembled from API data (customer_name, dropoff_address...) in
// src/pages/JobAssignment.jsx buildMapMarkers() (lines ~1324-1345) and WorkOrderDetail.jsx:288-314.

Sink 2 - public tracking page (no auth required):

// frontend src/pages/ServiceStatusPublic.jsx:151-187
// Leaflet bindPopup()/divIcon() interpolate order.mechanic_name, order.mechanic_phone,
// order.customer_name, order.dropoff_address directly into HTML strings (innerHTML semantics).
// Any visitor of /service-status/:token triggers execution.

Sink 3 - print job-assignment board:

// frontend src/pages/JobAssignment.jsx:1271-1305
// HTML built by concatenation (recipient_name, mechanic_name, work_order_number) then:
win.document.write(html); win.document.close();   // executes embedded scripts

Fix: sanitize on write (xss package is already installed) AND encode on read; replace dangerouslySetInnerHTML/string popups with React elements; purge stored payloads.

SR-02 — Default credentials + committed deployment secrets (CRITICAL)

// src/migrations/post/01_seed_demo.sql (in public repo)
INSERT INTO users ... ('admin', 'Demo@12345' ...);      // default admin password

// deploy/deploy-rhel.sh (in public repo - repo is public, verified via GitHub API)
DB_USER="root"
DB_PASS="[redacted]"                     // hardcoded MySQL root password
SERVER_IP="10.10.241.84"                 // internal server IP
JWT_SECRET=rhel-staging-jwt-secret-$(date +%s)   // timestamp-derived secret
// SMTP_* blank, but script writes .env with BACKEND_URL/FRONTEND_URL=http://{IP} (HTTP, no TLS)

No password-change-on-first-login logic exists in routes/auth.js (login only checks bcrypt match). The JWT secret is derived from a deploy timestamp - the window is guessable if deployment time is known.

Fix: private repos; rotate secrets; generate secrets at deploy time from openssl rand; force password change for seeded accounts; HTTPS everywhere.

SR-03 — SSRF in webhook delivery (HIGH)

// routes/webhooks.js - deliverWebhook():
const res = await fetch(endpoint.url, { method, headers, body, timeout: 10000 });
// endpoint.url is attacker-supplied (admin creates webhook). No scheme allow-list,
// no IP validation (RFC1918/link-local/loopback), no DNS-rebinding check, no redirect control.
// Live proof: delivery log recorded HTTP 405 from http://169.254.169.254/latest/meta-data/.

Fix: deny-list private/metadata ranges (169.254.0.0/16, 100.100.100.200, 10/8, 172.16/12, 192.168/16, ::1, 127/8), HTTPS-only, validate resolved IP before and after redirects, egress proxy.

SR-04 — Rate limiting missing on web/customer/super-admin auth (HIGH)

// lib/rate-limits.js defines mechanicLoginLimiter, mechanicOtpLimiter, mechanicPasswordResetLimiter.
// routes/mechanic-app.js is the ONLY file importing them.
// routes/auth.js (admin login, forgot-password), routes/customer-auth.js (register/login/forgot-password),
// routes/super-admin.js:50 (super-admin login) have no limiter.
// Live: 20 rapid /api/auth/login attempts → all 401, no 429, no delay.

Fix: apply limiter (per IP + per account) to all auth endpoints; lockout + captcha after N failures.

SR-05 — Unauthenticated trial provisioning / email bombing (HIGH)

// routes/public-api.js - POST /api/public/start-trial
// No auth, no captcha, no rate limit. Creates workshop + owner user + sends welcome email to
// attacker-supplied address. Live: workshops #2 and #3 created with vapt-rt-known@probe.local.
// Error differentiation (409 "already exists" vs 201) enables enumeration (VAPT FIND-012).

Fix: captcha + limiter; verify email before provisioning; cap trials per IP/email.

SR-06 — Unverified customers get full portal access (MEDIUM)

// routes/customer-auth.js - register() creates user with email_verified=0 and issues sessions.
// login() issues a JWT regardless of verification state (returns is_verified in the payload only).
// routes/customer-portal.js:44-56 - middleware injects req.customer; nothing checks email_verified.
// Live: is_verified=false session created work orders and read portal data (HTTP 200).

Fix: gate on email_verified=1; expire unverified sessions; require verification for write actions.

SR-07 — Mechanic GPS broadcast to all workshop-room members incl. customers (MEDIUM)

// lib/socket.js:63-65 - any JWT with workshop_id joins "workshop:{id}" room (customers included)
// routes/mechanics.js:596 - io.to(`workshop:${req.workshopId}`).emit('mechanic:location', {...lat,lng,phone...})
// routes/mechanics.js:605 - io.to(`track:${token}`).emit(...)
// Live customer JWT payload: {"role":"customer","workshop_id":1,...} - join capability confirmed.

Fix: role-check on join (admin/mechanic only); customers get track:{token} rooms only.

SR-08 — Public tracking token weakness + PII exposure (MEDIUM)

// routes/customer-portal.js:246 - service_status_token = crypto.randomBytes(6).toString('hex').toUpperCase()
//   → 48-bit, unguessable in practice, but legacy rows use 32-bit tokens (e.g. live A384F81275E8)
// routes/api-v1.js:357 - 'TR' + 48-bit token (OK)
// routes/service-status.js - GET /api/service-status/:token returns customer_name, addresses,
//   mechanic_name, mechanic_phone, service_bay_name with NO authentication (public link only).

Fix: 128-bit tokens for new rows and migration of legacy; drop mechanic phone from the public response; rate limit the endpoint.

SR-09 — JWTs in localStorage and in JSON responses (MEDIUM)

// routes/auth.js (login) returns token in JSON body; Set-Cookie also present (HttpOnly - good)
// frontend src/lib/api.js:  const token = localStorage.getItem('auth_token');  // used as Bearer
// frontend LoginPage.jsx: localStorage.setItem('auth_token', data.token)
// frontend SuperAdminLogin.jsx: localStorage.setItem('superAdminToken', data.token)
// Any XSS (SR-01) reads these keys directly - confirmed keys: auth_token, auth_workshop, crm_token,
// crm_user, superAdminToken, lang.

Fix: HttpOnly cookie-only sessions; keep token out of JSON; short TTL + refresh rotation (mechanic-app already implements rotation - reuse that pattern for web).

SR-10 — Missing security headers (CSP, HSTS) (MEDIUM)

// server.js - no helmet, no CSP, no HSTS anywhere in the app; nginx template in deploy-rhel.sh
// sets none either. Live headers confirm: x-frame-options DENY + nosniff present (set somewhere in
// prod nginx), but no CSP / HSTS / Referrer-Policy / Permissions-Policy / COOP / CORP.

Fix: add CSP (self-host Leaflet; note inline styles used), HSTS preload, Referrer-Policy, Permissions-Policy.

SR-11 — Uploads: extension-only validation (LOW)

// routes/uploads.js:23-46
const ALLOWED_IMAGE = /\.(jpg|jpeg|png|webp)$/i;
fileFilter: (_req, file, cb) => {
  if (!ALLOWED_IMAGE.test(file.originalname)) return cb(new Error('Only JPG, PNG, WEBP images are allowed'));
  cb(null, true);
}
// No magic-byte/MIME inspection. Stored with original extension; S3 backup uploads attacker-chosen
// originalname as the key and client-supplied mimetype (uploads.js:70-71).
// Mitigations present: X-Content-Type-Options nosniff; SVG not allowed; filenames server-generated.

Fix: validate magic bytes (file-type package), re-encode images, serve with Content-Disposition attachment policy, restrict S3 object ACLs.

SR-12 — Weak OTP generation + debug echo path (LOW)

// routes/mechanic-app.js - forgot-password:
const otp = String(Math.floor(100000 + Math.random() * 900000));   // Math.random() - not crypto-safe

// .env.example (public repo):
LOG_OTP_SECRET=true
// When true, the forgot-password response body includes the OTP ("_dev_otp") - if enabled in
// production, anyone who can trigger the flow reads the OTP directly.
// Note: mechanicOtpLimiter IS applied on this route (good).

Fix: crypto.randomInt(); force LOG_OTP_SECRET=false in production; short OTP TTL + max attempts.

SR-13 — Swagger UI exposed in production (LOW)

SR-15 — Client-controlled financials; CSV formula injection; security theater (INFO)

SR-16 — sanitizeNotes() blocklist bypassable and incomplete (INFO)

// routes/mechanics.js:38-52 - sanitizeNotes() strips script/style tags, on*="" (quoted only) and

// customer/work-order fields have no sanitization at all (SR-01).

Fix: use the xss package (already in dependencies) or an allow-list encoder; apply consistently at the write boundary for ALL free-text fields.

Code Hygiene / Maintenance Notes

  • xss package installed but unused - either use it (recommended) or remove it.
  • Duplicate super-admin implementations (super-admin.js vs super-admin-enhanced.js) - keep one RBAC path to avoid drift.
  • Multiple `"all permissions"` shortcuts (perms.all, perms.super_admin, perms.platform_owner in middleware/auth.js:141) - confirm no non-super-admin account can receive these flags.
  • Swagger spec duplicated in swagger.yaml (served at /api/docs) and exposed publicly - keep in sync or remove from prod.
  • `.env.example` documents LOG_OTP_SECRET default true - flip default to false.
  • Email templates build HTML with template literals interpolating user-controlled workshop/owner names (super-admin-enhanced.js:723-732, 1082-1090) - encode these to prevent email-header/HTML injection.

Addendum - Follow-up Assessment (2026-08-17): deployment surface beyond this codebase

Live testing of the additional targets (two.pioneeruae.com, one.pioneeruae.com, staging.pioneeruae.com, and raw 68.178.171.205:3000) found deployment-level issues. Full evidence is in the VAPT report (findings T2-001..T2-007). Code-relevant notes for the owner:

  • An unrelated Next.js application ("One Mobility Group") runs exposed on TCP 3000 with live API routes (/api/hello, /api/contact), no nginx/WAF, no TLS, and no security headers. It is not part of this codebase and should be firewalled/removed or brought behind the same hardening as the rest.
  • LOG_OTP_SECRET is confirmed OFF in production - live POST /api/mechanic-app/forgot-password returns no _dev_otp (mechanic-app.js:455-464 would add it if the env var were 'true'). Keep it disabled; also flip the .env.example default from true to false.
  • Client bundles of all four related sites were scanned (two.pioneeruae.com ~508 KB of chunks, One Mobility Group :3000, staging 595 KB, Mwasalat default-vhost 664 KB): no API keys, secrets, tokens, or credentials found in any bundle.
  • No real files exposed behind the SPA fallback: /.git/HEAD, /.env*, /backup.zip, /db.sql, /package.json all return HTTP 200 but with the same fallback HTML - no source or secret files are reachable via nginx on the marketing hosts.
  • Deployment hygiene: wildcard DNS + wildcard TLS cert (*.pioneeruae.com), public staging host, and a default vhost serving an unrelated brand's staging SPA - see T2-004, T2-005, T2-006.
